# 0004: Relational Core with Transactional Event Audit Logging

The platform must satisfy two distinct data demands: rapid relational queries for real-time leaderboards, moderation, and session dashboards, alongside an immutable, exportable log of every learning interaction as required by Section 36 of the PRD. We decided to implement normalized relational tables (`responses`, `points`, `whiteboards`, etc.) as the operational source of truth, while simultaneously appending an immutable entry to an `events` table within the same database transaction on every state change, rather than adopting pure event sourcing. This avoids complex event projection rebuilds and snapshot management during MVP development while guaranteeing transactional consistency and complete JSON audit history exportability.
